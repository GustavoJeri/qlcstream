# Integração contínua

O workflow `.github/workflows/ci.yml` executa em pull requests para `develop`, `main` e `integration/qlcstream`, em pushes nessas branches e manualmente pelo GitHub Actions. Há resultados independentes para **Backend** (Java 21, `./mvnw verify`), **Frontend** (Node 26, testes e compilação), **Windows launcher** e **Integration versions**. Falhas em qualquer etapa fazem seu job falhar.

O frontend usa o lockfile; o backend usa o Maven Wrapper. O workflow possui permissão de leitura do repositório, não conserva credenciais no checkout, fixa as ações por commit e limita a duração dos jobs. Execuções anteriores da mesma PR ou branch são canceladas quando outra é iniciada. Relatórios de teste do backend e saídas de teste ou compilação do frontend são guardados por sete dias quando um job falha, quando disponíveis. Não são incluídos `.env`, banco, arquivos de mídia ou configurações pessoais de serviços. As verificações não precisam de credenciais das integrações nem iniciam downloads.

Para repetir localmente, use Java 21 e Node 26. No backend, execute `./mvnw verify` (Windows: `.\mvnw.cmd verify`). No frontend, execute `npm ci`, `npm test -- --watch=false` e `npm run build`. `npm ci` recria `node_modules`; para preservar dependências locais, use uma cópia de trabalho isolada.

O CI informa resultados; para impedir merges sem aprovação dos checks, configure regras de proteção de branch no GitHub. Não há implantação ou publicação automática neste workflow.

O job **Windows launcher** executa `docs/validation/Test-WindowsLauncher.ps1` no Windows PowerShell 5.1 e PowerShell 7, sem instalar dependências. Cobre classificação de falhas, preservação de configuração, preparação inicial, reutilização, portas TCP/UDP e bloqueio concorrente. Docker/HTTP/navegador são simulados; sockets e arquivos são reais. A prova com Docker Desktop, documentada em [inicialização no Windows](inicializacao-windows.md), é uma validação local separada e não faz parte deste job.

O job **Integration versions** testa o verificador de versões e executa a [matriz real das imagens fixadas](versoes-integracoes.md): serviços em rede Docker interna, torrent privado de bytes próprios, fonte Torznab controlada, autenticação, APIs, reinício e cópia offline de volumes sintéticos. Não acessa trackers/fontes externos, contas pessoais ou volumes existentes. O build e a obtenção de imagens usam a rede antes dos testes. Resultados JSON com hashes sintéticos ficam em artefatos por sete dias; não incluem chave, banco ou credenciais. O runner hospedado é descartado pelo CI; localmente os volumes sintéticos são mantidos para inspeção.

Esse job também executa os testes do auxiliar de exclusão e `test-integration-file-actions.py`, com imagens de backend e frontend construídas explicitamente. O roteiro recusa puxar imagens ou compilar por conta própria e exige `--image`, `--frontend-image` e `--evidence-dir`. Usa projetos aleatórios, volumes próprios e nenhuma porta publicada; encerra somente seus serviços e preserva os volumes. Cobre cancelamento durante inclusão assíncrona e após reinício, transferência privada de bytes próprios, exclusão de um único arquivo com preservação de outro episódio, repetição, link externo e reconexão SSE real através do nginx. Apenas mensagens controladas de resultado são guardadas; logs de serviço e corpos remotos não são expostos.

Os testes de exclusão com descritores devem passar tanto no provedor Java que oferece `SecureDirectoryStream` quanto no runtime Alpine com o auxiliar incluído. No backend Windows nativo sem esses recursos, o teste confirma recusa sem alterar o arquivo. Isso não equivale a abrir VLC/Explorer no aplicativo Tauri; esse ensaio nativo continua separado.

Para ensaiar o desktop sem acessar a instalação diária, use uma cópia de compilação e um projeto Compose exclusivo. `QLCSTREAM_COMPOSE_PROJECT` no processo Tauri seleciona somente o backend desse projeto para descobrir a montagem `/data`; o padrão permanece `qlc-stream`. Compile o Angular com `--define 'QLCSTREAM_DESKTOP_API_ORIGIN="http://127.0.0.1:PORTA"'`, substituindo PORTA pela porta exclusiva da API sintética. O override aceita somente origem HTTP/HTTPS de loopback, sem credenciais, caminho, consulta ou fragmento. Sem override, o desktop usa `http://127.0.0.1:8080`; o navegador continua usando sua própria origem. Use também identificador Tauri e diretórios de perfil temporários na cópia de teste.

Em uma cópia combinada explicitamente com a PR complementar de backup, `python docs/validation/test-backup-v12.py --backend-image IMAGEM_BACKEND --frontend-image IMAGEM_FRONTEND` estende o ensaio de restauração com `deletion_requested` e cancelamento pendente. Exige as imagens já construídas e o roteiro original da PR #7; não integra essa PR à branch atual. Compara integralmente os registros de arquivos e downloads antes/depois, com e sem bytes de mídia. Remove somente contêineres e redes próprios já encerrados; preserva todos os volumes sintéticos.
