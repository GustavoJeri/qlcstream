# QLC Stream 0.1.0-rc.1 (candidata)

> **Estado:** release candidata (`candidate`), ainda sem tag pública nem publicação em `main`. Nenhuma alteração é aplicada automaticamente à instalação diária.

## Política de versionamento e tags

- Versões finais usam versionamento semântico `MAJOR.MINOR.PATCH` com tag Git `vMAJOR.MINOR.PATCH`.
- Candidatas de validação usam sufixo `-rc.N` (por exemplo `0.1.0-rc.1`) com tag opcional `vMAJOR.MINOR.PATCH-rc.N` criada somente após revisão e aprovação do CI.
- Os números internos de scaffold (`backend/pom.xml`, `frontend/package.json` e `frontend/src-tauri/*`) permanecem separados da versão pública definida em `VERSION`, `backend/src/main/resources/release-metadata.properties` e `RELEASE-MANIFEST.json`.

## Alterações

- Identidade unificada de versão em `VERSION` e `backend/src/main/resources/release-metadata.properties`, exposta em `GET /api/system/status` (sem cache) e na tela **Configurações**, sem consultar `.git`.
- Rótulos OCI (`org.opencontainers.image.version` e `org.opencontainers.image.revision`) nos Dockerfiles de `backend` e `frontend`.
- Empacotamento reproduzível em `scripts/qlc-release.py` com lista explícita de arquivos versionados, manifesto público `RELEASE-MANIFEST.json`, verificação de checksums SHA-256 e bloqueio de `.env`, `data/`, `.git`, fixtures de teste e segredos.
- Suporte do `scripts/qlc-backup.py` a instalações extraídas de pacote sem `.git`, validando integralmente o `RELEASE-MANIFEST.json` e os arquivos de execução em disco.
- Comando administrativo `scripts/qlc-release.py apply` para aplicar um novo pacote verificado sobre uma pasta extraída, preservando `.env` e `data/`.
- Consolida as entregas integradas em `integration/qlcstream`: diagnósticos reais das integrações e armazenamento, persistência cifrada com chave separada, assistente de primeira configuração, inicializador Windows, imagens fixadas por tag e digest, backup consistente/restauração isolada (formato 1) e correções de downloads e exclusão segura (migração Flyway `V12`).

## Requisitos

- Docker Desktop (Windows com Engine Linux) ou Docker Engine com Compose v2.
- Python 3.12 ou superior no host para verificação de pacote, conferência de versões das integrações e backup/restauração.
- Nenhuma instalação automática de dependências no host; contas e credenciais (TMDB, indexadores Prowlarr, senha do qBittorrent) continuam sendo configuradas explicitamente pelo usuário.

## Instalação limpa

1. Verifique o pacote antes de extrair:
   ```powershell
   python scripts/qlc-release.py verify --package qlcstream-0.1.0-rc.1.zip --checksums qlcstream-0.1.0-rc.1.sha256
   ```
2. Extraia o arquivo ZIP em uma pasta vazia dedicada (sem sobrepor outra instalação).
3. Dentro da pasta extraída (`qlcstream-0.1.0-rc.1`), confirme a integridade e a identidade sem depender de Git:
   ```powershell
   python scripts/qlc-release.py verify-dir
   python scripts/qlc-release.py inspect
   ```
4. No Windows, execute `iniciar-qlcstream.bat` (ou em qualquer sistema: copie `.env.example` para `.env`, revise as variáveis e execute `docker compose up -d --build`).
5. Confirme a versão em execução via `http://127.0.0.1:8080/api/system/status` ou na página **Configurações** em `http://127.0.0.1:4200`.

## Atualização

O uso diário (`iniciar-qlcstream.bat`) **não atualiza** código nem recria contêineres. Para atualizar administrativamente uma instalação extraída de pacote:

1. Confirme a versão atual (`python scripts/qlc-release.py inspect`) e guarde uma cópia da pasta e dos IDs das imagens atuais (`docker compose images`).
2. Pare normalmente os escritores, mantendo apenas o banco ativo:
   ```powershell
   docker compose stop --timeout 1800 frontend backend prowlarr qbittorrent
   ```
3. Gere e verifique um backup consistente (com ou sem `--include-media`, conforme o espaço disponível):
   ```powershell
   docker build -t qlcstream-backup-helper:1 scripts/backup
   python scripts/qlc-backup.py backup --project qlc-stream --vault qlcbackup-pre-update --key-vault qlcbackup-pre-update-key
   python scripts/qlc-backup.py verify --vault qlcbackup-pre-update --key-vault qlcbackup-pre-update-key
   ```
4. Verifique o novo pacote e aplique somente os arquivos do manifesto (preservando `.env` e `data/`):
   ```powershell
   python scripts/qlc-release.py verify --package qlcstream-<nova-versao>.zip --checksums qlcstream-<nova-versao>.sha256
   python scripts/qlc-release.py apply --package qlcstream-<nova-versao>.zip --checksums qlcstream-<nova-versao>.sha256 --target .
   ```
5. Reconstrua explicitamente `backend` e `frontend` informando versão e commit do manifesto e recrie apenas esses serviços (sem `down -v`):
   ```powershell
   docker compose build --build-arg QLCSTREAM_VERSION=<nova-versao> --build-arg QLCSTREAM_COMMIT=<commit-do-manifesto> backend frontend
   docker compose up -d --no-build --force-recreate backend frontend
   docker compose start prowlarr qbittorrent
   ```
6. Confirme pós-atualização: `/actuator/health`, `/api/system/status` (nova versão e esquema), `scripts/check-integration-versions.py` e integridade da biblioteca/integrações na interface.

## Recuperação

Se uma atualização falhar, **não** execute `flyway repair`, `baseline`, troca de chave de criptografia ou `docker compose down --volumes`.

1. Pare os serviços afetados para preservar o estado para análise.
2. Abra a cópia preservada da **versão anterior** (com seu `RELEASE-MANIFEST.json` ou checkout compatível e as imagens locais anteriores preservadas).
3. Restaure o backup pré-atualização em um destino novo e isolado:
   ```powershell
   python scripts/qlc-backup.py restore --vault qlcbackup-pre-update --key-vault qlcbackup-pre-update-key --target qlcbackup-recuperacao
   ```
4. Revise o ambiente e valide os serviços restaurados antes de adotar o destino recuperado. Veja detalhes completos em `docs/backup-restauracao.md` e `docs/versoes-atualizacao.md`.

## Limitações

- Canal suportado neste pacote: **Docker/Windows** (`compose.yaml` + inicializador Windows). O scaffold desktop Tauri (`frontend/src-tauri`) não é distribuído nem empacotado nesta candidata.
- O empacotamento garante reprodutibilidade do arquivo ZIP e do manifesto; o build das imagens de `backend` e `frontend` continua dependendo das bases Docker e dos repositórios Maven/npm.
- Não existe atualizador automático silencioso nem downgrade de esquema Flyway/PostgreSQL.
- A restauração de backup (formato 1) exige a mesma identidade de execução (versão/esquema/imagens) que originou o backup; pacotes de outra versão são recusados antes de criar qualquer destino.
